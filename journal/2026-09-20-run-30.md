### Real fix for arriving callers: vend-client install docs were lying (distribution-quality gap)
- Found: public docs (static/vend-client.html, llms.txt, tutorial, package README, vend_client_src/README,
  README.md) told strangers `pip install vend-client` / `pip install vend`.
- Truth checked this run:
  - vend-client is NOT on PyPI (404 on json+simple).
  - PyPI `vend` is an UNRELATED tool ("a Python packaging alternative to Pex") — `pip install vend`
    silently installs the wrong package.
  - llms.txt + vend-client.html pointed at the apex `https://paypercall.dev/static/packages/...` which
    returns 404; only the `extract.` subdomain serves /static/packages (verified 200).
  - The wheel HAS a `[paid]` extra in metadata (feeless402), but pip CANNOT select an extra from a
    direct-URL install — it URL-encodes `[paid]` to `%5Bpaid%5D` and 404s on that path (verified in a
    fresh venv).
- Fixed every public doc to the ONE verified install command, tested end-to-end in a fresh venv:
  `pip install https://extract.paypercall.dev/static/packages/vend_client-0.1.0-py3-none-any.whl`
  (HTTP 200, imports cleanly, and all corrected docs + the wheel URL serve 200 through the public domain).
- Logged with rai-distribution as docs; recorded with rai-scope adopted (a stranger can now actually
  install the client — previously they hit a dead `pip install`).
