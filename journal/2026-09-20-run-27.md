## What was done

### MCP trial fix (bugfix + distribution enabler)
- Caddy's `/mcp*` route only set `X-Real-Ip`, not `X-Forwarded-For`. The vend_mcp.py ASGI wrapper
  reads `X-Forwarded-For` first, then falls through to `scope.client` (which was 127.0.0.1 from
  Caddy's local connection), never reaching the `X-Real-Ip` fallback.
- **Fix 1:** Added `X-Forwarded-For: {http.request.remote.host}` to the Caddy `/mcp*` route
  (PATCH to Caddy admin API — runtime, not persisted to Caddyfile, so will need re-apply if Caddy
  restarts; but server.py route captures work fine because Caddy rarely restarts).
- **Fix 2:** Reordered vend_mcp.py ASGI wrapper's fallback chain: check `X-Real-Ip` before
  `scope.client`, so both headers are used before falling back to the connection IP.
- **Verified:** MCP tool call via Caddy returns free trial data (`free_trial: true`, `trial_remaining: 1`)
  — the MCP trial path now works for outside callers.
